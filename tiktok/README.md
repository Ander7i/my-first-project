# TikTok: статистика и публикация в пиковые часы

Консольный инструмент для своего TikTok-аккаунта. Раз в час снимает
статистику, по ней вычисляет, в какие часы ваша аудитория смотрит ролики,
и публикует ролики из очереди перед этими часами.

Работает только через официальное API TikTok: вход по OAuth, без паролей,
эмуляции телефона и обхода защит.

## Что умеет

- **Статистика** — подписчики, лайки, просмотры по дням и по каждому ролику:
  просмотры, прирост за сутки, лайки, комментарии, репосты, вовлечённость (ER).
- **Пиковые часы** — считаются по приросту просмотров ваших же роликов
  (подробно — в разделе «Как считаются пиковые часы»).
- **Очередь публикаций** — время перед пиком подбирается само, с лимитом
  роликов в день и интервалом между ними. Ролики выходят в том порядке, в
  каком вы их добавили.
- **Публикация** — сразу (`direct`) или черновиком во «Входящие» TikTok (`inbox`).
- Можно подключить несколько своих аккаунтов.

## Почему нет прогрева, автолайков и автопросмотров

Для лайков и просмотров у TikTok нет API. Такое делают только эмуляцией
телефона или браузера, а правила TikTok запрещают автоматизированные действия
в приложении. TikTok такие аккаунты распознаёт, и итог — теневой бан или
блокировка, то есть обратное тому, ради чего прогревают.

Прогрев нового аккаунта лучше сделать руками, это 15–30 минут в день:

- 3–5 дней просто смотрите ленту своей тематики, интересные ролики — до конца;
- ставьте лайки, пишите комментарии, подписывайтесь на то, что правда
  нравится, — лента и алгоритм подстроятся под нишу;
- заполните профиль: аватар, имя, описание;
- первые дни публикуйте по 1 ролику в день, не пачками.

## Что нужно знать про TikTok заранее

- **Нужно своё приложение** на [developers.tiktok.com](https://developers.tiktok.com/)
  — это бесплатно. Инструкция ниже.
- **Песочница (Sandbox)** работает без проверки приложения TikTok: до 10
  своих аккаунтов. Для личного использования этого хватает.
- **Сразу публиковать публичные ролики (`direct`) можно только после аудита**
  приложения в TikTok. До аудита видимость только `SELF_ONLY`, а аккаунт
  должен быть закрытым. Для аудита нужны политика конфиденциальности и
  демо-видео, и TikTok ждёт приложения для широкой аудитории — личный
  инструмент его может не пройти.
- Поэтому по умолчанию режим **`inbox`**: в нужное время ролик приходит
  черновиком во «Входящие» TikTok, вы открываете уведомление и публикуете.
  Подпись и видимость выбираются там же. Неопубликованных черновиков — не
  больше 5 за сутки.
- **Лимиты TikTok**: около 15 публикаций через API в сутки на аккаунт. Видео —
  MP4, MOV или WebM до 4 ГБ, 23–60 кадров в секунду, стороны от 360 до 4096
  пикселей, длительность — сколько разрешено аккаунту (обычно 3–10 минут).
- **Статистика — только по публичным роликам**: закрытые API не отдаёт.
- **Если аккаунт работает из России**: с марта 2022 года TikTok не даёт
  пользователям из России публиковать новые ролики. Это ограничение самого
  TikTok, инструмент его не обходит.
- Без API можно публиковать по расписанию прямо в
  [TikTok Studio](https://www.tiktok.com/tiktokstudio) — до 10 дней вперёд.
  Время для него подскажет команда `peak`.

## Установка

Нужен Python 3.10 или новее.

```bash
cd tiktok
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
```

Все команды дальше запускаются из папки `tiktok`.

## Приложение в TikTok for Developers

1. Зарегистрируйтесь на [developers.tiktok.com](https://developers.tiktok.com/).
2. Значок профиля → **Manage apps** → **Connect an app**.
3. **App details**: иконка 1024×1024, название, категория и описание — его
   увидят на экране входа. В **Platforms** выберите **Desktop**.
4. **Products** → **Add products**: добавьте **Login Kit** и **Content
   Posting API**.
   - В настройках Login Kit для Desktop укажите Redirect URI
     `http://localhost:3455/callback/`.
   - Для режима `direct` включите в Content Posting API **Direct Post**.
5. **Scopes**: `user.info.basic`, `user.info.stats`, `video.list` и право на
   публикацию — `video.upload` для `inbox` или `video.publish` для `direct`.
   Если `video.list` или `user.info.stats` в списке нет, добавьте продукт
   **Display API**.
6. Переключите приложение в **Sandbox**, создайте песочницу и в **Target
   users** добавьте свой аккаунт TikTok. Он может появиться в списке не сразу,
   а в течение часа.
7. Скопируйте **Client key** и **Client secret** из раздела **Credentials** в
   `.env` — в `TIKTOK_CLIENT_KEY` и `TIKTOK_CLIENT_SECRET`.

## Первый запуск

```bash
python -m tiktok_manager login      # откроется браузер, войдите и разрешите доступ
python -m tiktok_manager collect    # снять первую статистику
python -m tiktok_manager stats      # посмотреть её
```

**На сервере без браузера** войдите с флагом `--paste`: откройте ссылку на
любом устройстве, войдите, и браузер перейдёт на `localhost` с ошибкой — так и
должно быть. Скопируйте адрес из строки браузера и вставьте в консоль.
Другой способ — SSH-туннель `ssh -L 3455:localhost:3455 user@server` и обычный
`login`.

## Команды

| Команда | Что делает |
|---|---|
| `login` | подключить аккаунт (`--paste` — для сервера без браузера) |
| `accounts` | подключённые аккаунты и до какого числа действует доступ |
| `collect` | снять статистику прямо сейчас |
| `stats` | статистика аккаунта и последних роликов (`--days 14`, `--top 20`, `--update`) |
| `peak` | пиковые часы и ближайшие свободные слоты |
| `add ФАЙЛ…` | поставить ролики в очередь |
| `queue` | очередь (`--all` — вместе с давно завершёнными) |
| `remove N` | убрать ролик из очереди |
| `retry N` | вернуть ролик с ошибкой в очередь на ближайший пик |
| `run` | планировщик: статистика по расписанию и публикации |

Если подключено несколько аккаунтов, нужный указывается так: `-a "Имя"`.

## Очередь публикаций

```bash
python -m tiktok_manager add ролик.mp4 -c "Подпись #хештег"
python -m tiktok_manager add папка/                 # все ролики из папки
python -m tiktok_manager add ролик.mp4 --at "завтра 19:00"
python -m tiktok_manager run                        # без него ролики не уйдут
```

- **Подпись** — из `-c`, а без него из файла с тем же именем, что у ролика,
  и расширением `.txt`: `ролик.mp4` → `ролик.txt`. Удобно для пачки роликов.
- **Время** подбирается само. `--at` задаёт своё: `19:00`, `завтра 19:00`,
  `26.10 19:00`, `26.10.2026 19:00`.
- **В режиме `direct`** обязательно указать видимость:
  `--privacy PUBLIC_TO_EVERYONE` (все), `MUTUAL_FOLLOW_FRIENDS` (друзья),
  `FOLLOWER_OF_CREATOR` (подписчики) или `SELF_ONLY` (только вы). Комментарии,
  дуэты и stitch по правилам TikTok выключены, пока вы их не включите:
  `--allow-comments`, `--allow-duet`, `--allow-stitch`. Реклама своего
  бизнеса — `--promo`, оплаченная реклама бренда — `--paid`, ролик от ИИ — `--ai`.
- Перед публикацией настройки аккаунта сверяются заново: доступная видимость,
  максимальная длительность, запреты на комментарии и дуэты.

Как ведёт себя планировщик (`run`):

- Время публикации пропущено (компьютер спал, планировщик не работал) — ролик
  переносится на следующий пик, а не уходит в неудачное время.
- Временная ошибка TikTok или сети — повтор через 5 минут, всего до 3 попыток.
- Загрузка оборвалась — повторной отправки вслепую нет: сначала у TikTok
  выясняется, дошёл ли ролик. Так не бывает дублей.
- Если доступ к аккаунту истёк, планировщик пишет об этом в лог и ждёт нового
  `login`. Остальные аккаунты работают дальше.

## Как считаются пиковые часы

Планировщик раз в час сохраняет счётчики просмотров всех публичных роликов.
Прирост между двумя снимками раскладывается по часам суток в поясе `TIMEZONE`.
Так видно, когда аудитория действительно смотрит ролики именно этого аккаунта.

- Первые 6 часов после публикации не учитываются: в эти часы ролик набирает
  просмотры из-за самой публикации, и «пиком» иначе оказалось бы время, когда
  вы обычно публикуете.
- Промежутки длиннее 3 часов (планировщик не работал) пропускаются — их
  прирост по часам честно не разложить.
- Берутся последние 28 дней. Пока данных меньше 200 просмотров или 48 часов
  сбора, используются часы по умолчанию — 19:00, 13:00 и 16:00.
- Соседние часы сглаживаются, чтобы случайный всплеск не стал пиком. Часы
  слабее половины пика в расписание не попадают: ролик лучше перенести на
  завтра, чем выложить в «мёртвое» время.
- Каждый день используются лучшие `MAX_POSTS_PER_DAY` часов, разнесённые хотя
  бы на `MIN_GAP_HOURS`. Ролик выходит за `LEAD_MINUTES` до пика, чтобы успеть
  пройти обработку и набрать первые показы.

Точные часы активности подписчиков есть в TikTok Studio → Аналитика →
Подписчики. Если вписать их в `PEAK_HOURS`, они будут главнее статистики.

## Настройки

Всё задаётся в `.env`, пояснения — в `.env.example`.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` | — | ключи приложения |
| `TIKTOK_REDIRECT_URI` | `http://localhost:3455/callback/` | адрес возврата после входа |
| `PUBLISH_MODE` | `inbox` | `inbox` или `direct` |
| `TIMEZONE` | пояс компьютера | пояс аудитории, например `Europe/Moscow` |
| `PEAK_HOURS` | — | свои пиковые часы: `19,13` |
| `LEAD_MINUTES` | `60` | за сколько минут до пика публиковать |
| `MAX_POSTS_PER_DAY` | `2` | роликов в день, не больше |
| `MIN_GAP_HOURS` | `3` | часов между роликами, не меньше |
| `COLLECT_EVERY_MINUTES` | `60` | как часто снимать статистику |
| `DB_PATH` | `tiktok.db` | файл базы |

После смены `PUBLISH_MODE` войдите заново: режимам нужны разные права.

## Как держать запущенным

Планировщик работает, пока запущен процесс. Для сервера — systemd-юнит,
например `/etc/systemd/system/tiktok-planner.service`:

```ini
[Unit]
Description=TikTok planner
After=network-online.target

[Service]
WorkingDirectory=/opt/my-first-project/tiktok
ExecStart=/opt/my-first-project/tiktok/.venv/bin/python -m tiktok_manager run
Restart=always
RestartSec=10
User=botuser

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now tiktok-planner
sudo journalctl -u tiktok-planner -f     # смотреть лог
```

На Windows достаточно оставить открытым окно с `python -m tiktok_manager run`
или добавить эту команду в Планировщик заданий.

## Данные

Всё хранится локально в `tiktok.db` (SQLite): токены доступа, статистика и
очередь. Файл базы и `.env` никому не передавайте и не выкладывайте. Доступ
к аккаунту можно отозвать в настройках TikTok, в списке приложений с доступом
к аккаунту.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest
ruff check .
```

Тесты покрывают вход с PKCE и локальным сервером, обновление и смену токенов,
разбор ошибок TikTok, разбиение файла на части по правилам TikTok,
длительность MP4, расчёт пиков (переход на зимнее время, пояса со сдвигом в
полчаса, исключение первых часов после публикации), подбор слотов с лимитами,
повторы без дублей и команды консоли.

## Структура

```
tiktok_manager/
├── __main__.py      запуск: python -m tiktok_manager
├── cli.py           команды консоли
├── config.py        чтение .env
├── auth.py          вход по OAuth с PKCE, локальный сервер для ответа TikTok
├── api.py           клиент TikTok API: токены, статистика, публикация
├── video.py         проверка файла, длительность MP4, разбиение на части
├── db.py            SQLite: аккаунты, снимки статистики, очередь
├── analytics.py     пиковые часы и просмотры по дням
├── slots.py         подбор времени публикации
├── planner.py       связка базы и расчётов
├── publisher.py     отправка роликов и отслеживание их статуса
├── runner.py        планировщик
└── report.py        отчёты для консоли
```
