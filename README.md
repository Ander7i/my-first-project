# Бот подработки «тайный покупатель»

Телеграм-бот, который ведёт весь процесс: публикует набор в группе, отвечает
на вопросы участников, собирает анкеты исполнителей, рассылает им задания,
принимает отчёты с фото и ведёт учёт выплат.

## Что умеет

**В группе**
- публикует объявление о наборе с кнопкой на анкету (`/post`);
- сам отвечает на типовые вопросы: сколько платят, что делать, нужна ли
  машина, «это не развод?» и т. д. — список в `bot/texts.py`, `FAQ`;
- встречает новых участников;
- анонсирует новые задания (`/tasklist` → «В группу»).

**В личке с исполнителем**
- объясняет, как всё работает, и берёт согласие на обработку данных;
- проводит по анкете: город, возраст, авто, связь, интересные категории;
- присылает подходящие задания и даёт их взять кнопкой;
- проводит по сдаче отчёта: фото → вопросы чек-листа → комментарий;
- сообщает, что отчёт принят, вернулся на доработку или оплачен;
- по `/stop` полностью удаляет данные человека.

**Администратору**
- `/newtask` — создать задание и сразу разослать подходящим исполнителям;
- `/tasklist` — список заданий, повторная рассылка, закрытие, анонс в группу;
- `/reports` — отчёты на проверке, кнопки «Принять» / «На доработку»;
- `/payouts` — сколько и кому к выплате, отметка об оплате;
- `/announce` — сообщение всем активным исполнителям;
- `/admin` — сводка: сколько исполнителей, заданий, отчётов, выплат.

## Запуск

Нужен Python 3.11 или новее.

### 1. Создать бота

Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, задайте имя
и получите токен вида `123456789:AAE...`.

### 2. Установить

```bash
git clone https://github.com/Ander7i/my-first-project.git
cd my-first-project
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Настроить

```bash
cp .env.example .env
```

Откройте `.env` и впишите токен в `BOT_TOKEN`. Остальное заполним на ходу.

### 4. Узнать свой ID

Запустите бота (`python -m bot` — он поругается на `ADMIN_IDS`, если там
ничего нет, поэтому пока впишите туда любое число, например `1`), напишите
ему в личку `/myid` и впишите полученное число в `ADMIN_IDS`. Если
администраторов несколько — через запятую.

### 5. Подключить группу

Добавьте бота в группу и сделайте **администратором** — иначе он не сможет
там писать. Затем напишите в группе `/chatid` и впишите полученный ID
(отрицательное число) в `GROUP_CHAT_ID`.

### 6. Разрешить боту видеть сообщения группы

По умолчанию Telegram показывает боту в группе только команды и упоминания.
Чтобы он отвечал на вопросы участников, в @BotFather:

```
/setprivacy → выберите бота → Disable
```

Без этого шага автоответы работают только когда бота упомянули через `@` или
ответили на его сообщение. Всё остальное работает одинаково.

### 7. Запустить

```bash
python -m bot
```

Дальше: напишите боту `/post` — он опубликует набор в группе. Люди нажимают
кнопку, заполняют анкету и попадают в базу. Создавайте задания через
`/newtask`.

## Если Telegram недоступен с сервера

С части хостингов `api.telegram.org` не открывается напрямую. Тогда впишите
в `.env` адрес прокси:

```
PROXY_URL=http://user:pass@host:3128
```

Поддерживаются HTTP и SOCKS5 (`socks5://...`). Если переменная не задана,
бот подхватит системную `HTTPS_PROXY`, когда она есть. Для работы через
прокси нужен пакет `aiohttp-socks` — он уже в `requirements.txt`.

## Как это держать запущенным

Бот работает, пока запущен процесс. Для постоянной работы на сервере —
systemd-юнит, например `/etc/systemd/system/shopper-bot.service`:

```ini
[Unit]
Description=Secret shopper bot
After=network.target

[Service]
WorkingDirectory=/opt/shopper-bot
ExecStart=/opt/shopper-bot/.venv/bin/python -m bot
Restart=always
RestartSec=5
User=botuser

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now shopper-bot
sudo journalctl -u shopper-bot -f      # смотреть логи
```

## Настройка под себя

| Что поменять | Где |
|---|---|
| Все тексты, что говорит бот | `bot/texts.py` |
| Автоответы в группе | `bot/texts.py`, переменная `FAQ` |
| Категории проверок | `.env`, переменная `CATEGORIES` |
| Вопросы анкеты | `bot/handlers/survey.py` + `bot/states.py` |
| Чек-лист задания | задаётся при создании задания в `/newtask` |

Чек-лист вводится построчно — каждая строка станет отдельным вопросом,
который бот задаст исполнителю при сдаче отчёта.

## Данные и приватность

Бот хранит только то, что человек сам ввёл в анкете, и только после явного
согласия на первом экране. Лежит это в локальном файле SQLite (`shopper.db`),
никуда не отправляется. По команде `/stop` запись и все связанные отчёты
удаляются полностью.

Два технических ограничения Telegram, о которых стоит знать:

- **Бот не может написать человеку первым.** Диалог начинает только сам
  человек — поэтому в группе стоит кнопка со ссылкой на бота. Рассылка
  заданий работает лишь по тем, кто уже заполнил анкету.
- **Бот не видит список участников группы** и не собирает их профили. В базу
  попадают только те, кто сам нажал кнопку и прошёл анкету.

В текстах бота намеренно написано, что проект никогда не просит предоплату,
данные карт и коды из СМС: под видом «работы тайным покупателем» часто
работают мошенники, и участникам полезно знать, чего не должно быть.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest        # 48 тестов
ruff check bot tests
```

Тесты покрывают подбор исполнителей по городу и категории, выдачу слотов
(включая гонку, когда задание берут одновременно), жизненный цикл отчёта,
рассылку с блокировками, разбор чек-листа и чтение настроек.

## Структура

```
bot/
├── __main__.py        запуск, меню команд
├── config.py          чтение .env
├── db.py              SQLite: пользователи, задания, заявки, отчёты
├── texts.py           все тексты и FAQ
├── keyboards.py       инлайн-кнопки
├── states.py          состояния диалогов
├── callbacks.py       данные кнопок
├── utils.py           карточки, рассылка, экранирование
└── handlers/
    ├── start.py       согласие, профиль, /stop
    ├── survey.py      анкета
    ├── performer.py   взять задание, сдать отчёт
    ├── admin.py       задания, проверка отчётов, выплаты
    └── group.py       автоответы в группе, приветствие
```

### Про хранение состояния диалогов

Незаконченные диалоги (анкета или отчёт на середине) держатся в памяти
процесса. После перезапуска бота такой диалог придётся начать заново —
сами анкеты, задания и отчёты в базе, с ними ничего не случится. Если это
станет мешать, в aiogram подключается внешнее хранилище (например Redis)
заменой `MemoryStorage` в `bot/__main__.py`.
